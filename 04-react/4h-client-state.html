Client State Management

Once you've pushed server state into TanStack Query, what's left as "state"? Form drafts, UI toggles, navigation state, user preferences. For that you rarely need Redux.

OptionPick when
Local useStateThe state belongs to one component (plus close children). Default.
Lifted state + propsTwo sibling components need it. Hoist to common parent.
ContextRarely-changing global data: theme, current user. Never for fast-updating state.
ZustandGlobal or cross-cutting state that updates often. Tiny API, no provider needed, hooks-based. The recommended default for 2026.
Redux ToolkitLarge teams, complex state with time-travel debugging, or existing Redux codebases. Don't pick for a new small app.
Jotai / RecoilAtom-based model fits your domain better than store-based.
// Zustand
import { create } from "zustand";

const useCart = create((set) => ({
  items: [],
  add: (item) => set(s => ({ items: [...s.items, item] })),
  remove: (id) => set(s => ({ items: s.items.filter(i => i.id !== id) })),
}));

function CartCount() {
  const count = useCart(s => s.items.length);  // selector → re-render only on length change
  return {count};
}

Zustand with Immer middleware — nested updates without spread hell

For deeply nested state, spreading every level is error-prone. The immer middleware lets you write mutating code; Immer produces a new immutable object internally.

import { create } from "zustand";
import { immer } from "zustand/middleware/immer";

const useSettings = create(immer((set) => ({
  user: { profile: { name: "", bio: "" } },
  setName: (name) => set(state => { state.user.profile.name = name; }),
  // No spread chain needed — Immer handles immutability
})));

URL state — query params as a store

Filter values, pagination, selected tabs — anything a user should be able to bookmark or share belongs in the URL, not in useState. In Next.js App Router, use useSearchParams (read) and useRouter/Link (write). In plain React Router, use the useSearchParams hook from react-router-dom.

"use client";
import { useSearchParams, useRouter } from "next/navigation";

function FilterBar() {
  const params = useSearchParams();
  const router = useRouter();
  const status = params.get("status") ?? "all";

  function setStatus(s) {
    const next = new URLSearchParams(params);
    next.set("status", s);
    router.push(`?${next}`);   // updates URL → component re-renders with new params
  }

  return ;
}

URL state survives page refresh, works with the back button, and is shareable — it's a better default than useState for anything navigation-related.

Python bridge

Python web apps (Flask, Django) put filter state in query params by default because there's no persistent client memory between requests. React developers often default to useState because it's easy — but that breaks the back button and sharing. Defaulting to URL state is the right instinct if you're coming from a server-rendered background.
