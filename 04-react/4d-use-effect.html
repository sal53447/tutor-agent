Part 4 · React · 4d

useEffect Properly

The most misused hook. The React team has written essays titled "You might not need an Effect." Read this section twice.

The real mental model

useEffect is for synchronizing with an external system — a DOM API, subscription, timer, network. It's not "do something after render." If your effect doesn't interact with anything outside React, you probably don't need it.

useEffect(() => {
  const ctrl = new AbortController();
  setIsLoading(true);
  fetch(url, { signal: ctrl.signal })
    .then(r => r.json())
    .then(data => { setData(data); setIsLoading(false); })
    .catch(err => {
      if (err.name !== "AbortError") { setError(err); setIsLoading(false); }
    });

  return () => ctrl.abort();          // cleanup
}, [url]);                            // re-runs when url changes

Things most people reach for useEffect for — and shouldn't

  • "Compute derived state from props" — just compute inline or with useMemo. Don't mirror into useState + effect.
  • "Reset state when prop changes" — use key to remount.
  • "Call a function on a button click" — put it in the event handler.
  • "Fetch data" — use TanStack Query / SWR / the framework's data-fetching primitives (covered in 4g).
Next.js bridge

In Next.js App Router you won't use useEffect for fetching at all — Server Components fetch directly in the component body (no hooks, just await fetch()). useEffect fetches are a client-only, pre-RSC pattern. If you're building on Next.js, this whole section is about the small category of genuinely external synchronization (WebSockets, analytics, DOM measurements), not data loading.

Strict Mode double-invocation

In dev, React intentionally runs effects twice to surface cleanup bugs. If your effect "stops working" in dev but not prod, you're missing a cleanup. This isn't a bug in React; it's a lint for your effect.

useLayoutEffect — the synchronous sibling

useLayoutEffect fires synchronously after DOM mutations but before the browser paints. Use it only for DOM measurements (reading element size/position to reposition a tooltip, for example). Everything else: use useEffect. useLayoutEffect blocks painting — it will hurt perceived performance if misused, and it throws on the server (SSR), so Next.js Server Components will error if it's imported server-side.

const ref = useRef(null);
const [height, setHeight] = useState(0);
useLayoutEffect(() => {
  // runs after DOM update, before paint — safe to read layout
  setHeight(ref.current.getBoundingClientRect().height);
}, []);
Review flags
  • Missing dependencies in the deps array. react-hooks/exhaustive-deps rule — never suppress without a reason comment.
  • Effect with an empty deps array that captures a prop. Almost always a stale closure bug.
  • Missing cleanup on subscriptions, timers, event listeners, aborts.
  • Effect that mutates state every render. Infinite loop.
  • isLoading never set to false on the error path — spinner runs forever.
