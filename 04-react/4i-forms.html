Forms — react-hook-form + Zod

Controlled vs uncontrolled: in controlled inputs, React state is the source of truth. In uncontrolled, the DOM is. Modern approach: react-hook-form is uncontrolled (faster, less re-rendering), with Zod for validation.

Same schema, client and server

Share the Zod schema between the React form and your Express / server action. Validation logic lives in one file; types are derived for both. Divergence is impossible.

React 19 native form Actions — the Next.js App Router pattern

React 19 adds first-class support for form submissions via Actions. Instead of wiring up onSubmit handlers manually, you pass an async function directly to <form action=>. Two new hooks wire up state and pending feedback.

  • useActionState(action, initialState) — returns [state, formAction, isPending]. state is whatever your action returns; isPending is true while the action is running.
  • useFormStatus() — must be called inside a component that is a child of the <form>. Returns { pending }. Lets a submit button know when any form above it is busy, without prop drilling.

This is the dominant pattern in Next.js App Router

Next.js Server Actions are async functions marked with "use server" that run on the server. You pass one directly as the action prop. useActionState manages the round-trip state. No API route needed for simple mutations. This replaces the onSubmit → fetch → setState dance for most form use-cases.

react-hook-form vs Actions — pick based on use-case

react-hook-form + Zod: complex client-side forms with many fields, real-time validation, field arrays, multi-step. Native Actions: simple mutations tied to Next.js Server Actions where progressive enhancement matters. They're complementary — react-hook-form can wrap an Action as its submit handler.
