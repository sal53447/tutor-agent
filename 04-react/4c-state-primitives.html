Part 4 · React · 4c

State Primitives — useState, useReducer

const [count, setCount] = useState(0);

// Setter accepts a value OR a function (use the function form when the new value
// depends on the previous — avoids stale closures):
setCount(c => c + 1);

// Lazy init — runs ONCE on mount. Use for expensive defaults.
const [items, setItems] = useState(() => loadFromStorage());

Immutability invariant

React detects changes by reference equality (===). If you mutate state in place, React can't tell anything changed — no re-render. Always produce a new object / array.

// BAD
user.name = "new";
setUser(user);                // same ref, no re-render

// GOOD
setUser({ ...user, name: "new" });

// Arrays:
setItems([...items, newItem]);                          // append
setItems(items.filter(x => x.id !== removedId));        // remove
setItems(items.map(x => x.id === id ? { ...x, ...p } : x));  // update one

When useReducer beats useState

When state has multiple related fields that update together ("complex transitions"), or when next state depends on previous + an event. Reducer makes transitions explicit and testable.

const [state, dispatch] = useReducer(reducer, initialState);

function reducer(state, action) {
  switch (action.type) {
    case "add": return { ...state, items: [...state.items, action.item] };
    case "clear": return { ...state, items: [] };
    default: throw new Error();
  }
}

useReducer — lazy initializer (third argument)

Like useState's function form, you can pass an init function as the third argument. React calls init(initialArg) once on mount. Use this when the initial state is expensive to compute or comes from a transformation of some argument.

function init(count) {
  return { items: [], count };   // runs once, not on every render
}

const [state, dispatch] = useReducer(reducer, 0, init);
// state → { items: [], count: 0 }

useRef as a non-rendering instance variable

When you need to track something across renders without triggering a re-render (interval IDs, previous values, abort controllers), reach for useRef. Covered in detail in 4e, but worth knowing it exists before you instinctively put interval IDs into state.

Forward pointer

When state needs to escape a single component and be shared across the app, see 4h — Client State Management (Zustand, Context). Don't hoist state just to hoist it; lift it when two sibling components genuinely need the same piece.

Self-check
  1. Why does setUser(user) after mutating user.name not trigger a re-render?
  2. You have a form with 8 fields that submit together. useState or useReducer?
  3. What's the difference between useState(heavyFn()) and useState(heavyFn)?

Answers: 1. Same object reference — React's equality check passes, no re-render scheduled. 2. useReducer — transitions between field states are explicit and easier to test. 3. First calls heavyFn on every render; second is lazy init and calls it only on mount.
