Node / Express backend config

Node's native ESM resolver is stricter than a bundler's. Use moduleResolution: "nodenext" and set module to match:

{
  "compilerOptions": {
    "target": "ES2022",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "strict": true,
    "noUncheckedIndexedAccess": true,
    "skipLibCheck": true,
    "resolveJsonModule": true,
    "esModuleInterop": true,
    "outDir": "dist",
    "rootDir": "src"
  },
  "include": ["src"]
}
Module / moduleResolution must match

With moduleResolution: "NodeNext", import paths in your source must include the .js extension — even though you're writing .ts files. Node resolves the emitted output, not the source. Bundlers ("bundler" resolution) don't have this requirement.

Start here

For new projects, turn on strict: true, noUncheckedIndexedAccess: true, and verbatimModuleSyntax: true. These three settings catch the overwhelming majority of bugs strict alone misses. @total-typescript/tsconfig is a popular preset.

Key flags explained

  • strict — turns on all strict-mode flags. Non-negotiable.
  • outDir / rootDir — tell tsc where to write compiled output and where source lives. Without these, .js files land next to .ts files.
  • noUncheckedIndexedAccess — arr[0] is typed as T | undefined. Catches "forgot the empty array" bugs. See 2f for what this means in practice.
  • exactOptionalPropertyTypes — distinguishes { x?: string } from { x: string | undefined }. Prevents sneaky bugs where undefined is assigned explicitly.
  • verbatimModuleSyntax — forces explicit import type / export type. Fixes erasure weirdness with bundlers.
  • isolatedModules — required when using Vite, SWC, or esbuild. They transpile file-by-file without a project graph.
  • moduleResolution: "bundler" — the modern default for non-Node codebases.
paths aliases are compile-time only

The paths field tells TS how to resolve @/* imports for type checking. It does not teach Node how to resolve them at runtime. You need bundler support (Vite, webpack, Next.js) or a runtime helper (tsconfig-paths) for paths to work outside a bundler. If you ship a plain Node script with tsc, paths aliases will silently fail at runtime.
