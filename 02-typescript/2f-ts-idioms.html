Part 2 · TypeScript · 2f

TS Idioms

any vs unknown

  • any — opts out of type checking. Poisons whatever it touches. Avoid.
  • unknown — the safe top type. You must narrow before using. Prefer this.
function parse(raw: unknown) {
  if (typeof raw === "string") return raw.toUpperCase();  // narrowed
  if (raw instanceof Error) return raw.message;
  throw new Error("unexpected");
}

Type guards — custom predicates

type Cat = { kind: "cat"; meows: boolean };
type Dog = { kind: "dog"; barks: boolean };

function isCat(x: Cat | Dog): x is Cat {
  return x.kind === "cat";
}

in narrowing — discriminated unions without a kind field

When a union lacks a shared discriminant field, use in to check for a property that's unique to one branch.

type ApiSuccess = { data: unknown };
type ApiError   = { error: string; code: number };
type ApiResult  = ApiSuccess | ApiError;

function handle(result: ApiResult) {
  if ("error" in result) {
    // result: ApiError
    console.error(result.code, result.error);
  } else {
    // result: ApiSuccess
    process(result.data);
  }
}

// Also works when one branch has an optional field the other doesn't
type WithId    = { id: string; name: string };
type WithoutId = { name: string };
function process(x: WithId | WithoutId) {
  if ("id" in x) console.log(x.id);  // x: WithId
}

Assertion functions

An assertion function narrows the type for all code after the call. If the assertion throws, TS knows the variable is narrowed in the success path.

function assertIsString(x: unknown): asserts x is string {
  if (typeof x !== "string") throw new Error(`Expected string, got ${typeof x}`);
}

function assertDefined(x: T | null | undefined): asserts x is T {
  if (x == null) throw new Error("Expected defined value");
}

// Usage:
const raw: unknown = JSON.parse(input);
assertIsString(raw);
raw.toUpperCase();   // OK — TS knows raw: string after the call
Assertion vs type guard

A type guard (x is T return) is for if branches. An assertion function (asserts x is T) is for "throw if wrong" — it narrows unconditionally for the rest of the scope. Use assertions for invariants, guards for conditional branches.

Type assertions with as

// Legitimate: you know more than TS — e.g. after a DOM query
const input = document.getElementById("search") as HTMLInputElement;

// Also legitimate: narrowing after Zod parse (result.data is already safe)
const user = result.data as User;

// Dangerous: bypasses all checks — only use as last resort
const x = someOpaque as unknown as SpecificType;  // double-cast is a red flag
as is a cast, not a conversion

as does not transform the value — it only silences the type checker. If the runtime value doesn't match, you get silent corruption, not an error. When you reach for as, ask: can I use a type guard, assertion function, or Zod parse instead?

Exhaustiveness with never

function area(s: Shape): number {
  switch (s.kind) {
    case "circle": return Math.PI * s.r ** 2;
    case "square": return s.side ** 2;
    default:
      const _never: never = s;  // compile error if we add a new kind
      throw new Error("unreachable");
  }
}

noUncheckedIndexedAccess in practice

When this flag is on (recommended — see 2e), array indexing returns T | undefined. This forces you to handle the empty-array case.

const items = ["a", "b", "c"];

const first = items[0];           // string | undefined (flag is on)
first.toUpperCase();              // Error: first might be undefined

// Handle it:
const first2 = items[0];
if (first2 !== undefined) first2.toUpperCase();   // OK

// Or: use array methods that don't require indexing
const first3 = items.at(0);      // string | undefined — same effect, cleaner

satisfies — validate shape without widening

See 2d for the full explanation. The key payoff: you get a compile-time shape check and TS keeps the literal/narrower types for use after the declaration.

// satisfies is most useful when you need BOTH:
// 1. a constraint check (the value must match a shape)
// 2. preserved inference (TS should know the concrete types)

type Theme = { colors: Record };

const theme = {
  colors: {
    primary: "#0070f3",
    danger: "#ff0000",
  },
} satisfies Theme;

theme.colors.primary.startsWith("#");   // OK — primary: string (not string | undefined)
// Without satisfies (using : Theme), TS widens to Record
// and you lose autocomplete on the specific keys.

Branded types — nominal typing on demand

type UserId = string & { __brand: "UserId" };
type OrderId = string & { __brand: "OrderId" };

function asUserId(s: string): UserId { return s as UserId; }
// Now UserId and OrderId are NOT assignable to each other
