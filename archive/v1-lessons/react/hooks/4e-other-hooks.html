Other Core Hooks

useMemo and useCallback — when they're real

Not an optimization by default. They're tools for maintaining referential equality so that child components (wrapped in memo) or downstream hooks don't invalidate. If nothing downstream cares about the reference, they're pure overhead.

// Worth it — ExpensiveList is wrapped in React.memo; items must be the same ref
const items = useMemo(() => rawData.filter(activeFilter), [rawData, activeFilter]);

// Worth it — callback is in an effect's deps, we don't want to re-run the effect
const onSubmit = useCallback((data) => save(data, apiKey), [apiKey]);

// NOT worth it — nothing downstream uses referential equality
const doubled = useMemo(() => count * 2, [count]);  // just compute inline

useRef — two jobs

// 1. DOM access
const inputRef = useRef(null);
useEffect(() => { inputRef.current.focus(); }, []);
return <input ref={inputRef} />;

// 2. Mutable instance variable — doesn't cause re-render
const intervalRef = useRef();
useEffect(() => {
  intervalRef.current = setInterval(tick, 1000);
  return () => clearInterval(intervalRef.current);
}, []);

useContext — global-ish state

const ThemeCtx = createContext("light");
function App() {
  return (
    <ThemeCtx.Provider value="dark">
      <Page />
    </ThemeCtx.Provider>
  );
}
function Page() {
  const theme = useContext(ThemeCtx);
  return <div data-theme={theme}>…</div>;
}
Context perf trap

Every consumer re-renders when the context value reference changes. If your context value is an inline {value, setValue} object, every Provider render creates a new object and invalidates every consumer. Memoize the value. For state that updates often, don't use Context; reach for Zustand or similar.

Newer hooks worth knowing

  • useId — stable unique ID, SSR-safe. Use for form label associations.
  • useTransition — mark a state update as non-urgent. UI stays responsive during expensive renders.
  • useDeferredValue — render a stale value while preparing a fresh one.
  • useOptimistic — optimistic UI state paired with server actions (Next.js).

useTransition — keeping the UI responsive

Wrap an expensive state update in startTransition. React can interrupt the transition render if higher-priority work (keystrokes, clicks) arrives. The isPending flag lets you show a loading indicator without a full spinner.

function SearchPage() {
  const [query, setQuery] = useState("");
  const [results, setResults] = useState([]);
  const [isPending, startTransition] = useTransition();

  function handleChange(e) {
    const q = e.target.value;
    setQuery(q);                         // urgent — update input immediately
    startTransition(() => {
      setResults(expensiveSearch(q));    // non-urgent — can be interrupted
    });
  }

  return (
    <>
      <input value={query} onChange={handleChange} />
      {isPending ? <span>Searching…</span> : <ResultList items={results} />}
    </>
  );
}

useDeferredValue — stale-while-fresh

Accepts a value; returns a deferred copy that lags behind while a fresh render is in progress. Useful when you don't own the state update (e.g., it comes from a parent) but still want to deprioritize the expensive downstream render.

function FilteredList({ query }) {
  const deferred = useDeferredValue(query);
  // deferred === previous query while fresh query is rendering
  const filtered = useMemo(() => bigList.filter(i => i.includes(deferred)), [deferred]);
  return <List items={filtered} />;
}

useOptimistic — immediate feedback before the server responds

Shows optimistic state instantly; reverts to the real state once the server action resolves (success or failure).

function TodoList({ todos, addTodo }) {
  const [optimisticTodos, addOptimistic] = useOptimistic(
    todos,
    (current, newTodo) => [...current, { ...newTodo, pending: true }]
  );

  async function handleAdd(formData) {
    const title = formData.get("title");
    addOptimistic({ id: crypto.randomUUID(), title });  // instant
    await addTodo(title);                                // real server call
  }

  return (
    <form action={handleAdd}>
      <ul>
        {optimisticTodos.map(t => (
          <li key={t.id} style={{ opacity: t.pending ? 0.5 : 1 }}>{t.title}</li>
        ))}
      </ul>
      <input name="title" /><button>Add</button>
    </form>
  );
}

use() — React 19's resource unwrapper

use() is unlike other hooks: it can be called conditionally and inside loops. It does two things:

  • Unwrap a Promise — suspends the component until the promise resolves (requires a <Suspense> boundary above).
  • Unwrap a Context — same as useContext but usable conditionally.
import { use, Suspense } from "react";

// Unwrap a promise (component suspends while pending)
function UserCard({ userPromise }) {
  const user = use(userPromise);   // throws if pending → Suspense catches it
  return <h2>{user.name}</h2>;
}

// Usage: pass the promise in, don't await it
function Page() {
  const promise = fetchUser(42);   // initiate fetch outside the suspending component
  return (
    <Suspense fallback={<Skeleton />}>
      <UserCard userPromise={promise} />
    </Suspense>
  );
}

// Unwrap context conditionally (valid — use() can be in an if)
function MaybeThemed({ themed }) {
  const theme = themed ? use(ThemeCtx) : "light";
  return <div data-theme={theme} />;
}
Create the promise outside the rendering component

If you write const user = use(fetchUser(id)) directly, a new promise is created every render → infinite suspension loop. Create the promise in a parent, a cache, or a Server Component, then pass it down.
