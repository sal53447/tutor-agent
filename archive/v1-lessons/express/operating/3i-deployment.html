Deployment & Ops

Dockerfile — the production shape

# Multi-stage build: smaller final image
FROM node:20-alpine AS deps
WORKDIR /app
COPY package.json pnpm-lock.yaml ./
RUN corepack enable && pnpm install --frozen-lockfile

FROM node:20-alpine AS build
WORKDIR /app
COPY --from=deps /app/node_modules ./node_modules
COPY . .
RUN corepack enable && pnpm build

FROM node:20-alpine AS runtime
WORKDIR /app
ENV NODE_ENV=production
COPY --from=deps /app/node_modules ./node_modules
COPY --from=build /app/dist ./dist
COPY package.json ./
USER node
EXPOSE 3000
CMD ["node", "dist/server.js"]

docker-compose.yml — local dev stack

services:
  app:
    build: .
    ports: ["3000:3000"]
    environment:
      NODE_ENV: development
      DATABASE_URL: postgresql://dev:dev@postgres:5432/myapp
      REDIS_URL: redis://redis:6379
    volumes:
      - .:/app              # mount source for hot reload
      - /app/node_modules   # keep container's node_modules
    depends_on:
      postgres: { condition: service_healthy }
      redis:    { condition: service_healthy }
    command: npx tsx watch src/server.ts

  postgres:
    image: postgres:16-alpine
    environment: { POSTGRES_USER: dev, POSTGRES_PASSWORD: dev, POSTGRES_DB: myapp }
    ports: ["5432:5432"]
    volumes: [postgres_data:/var/lib/postgresql/data]
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U dev"]
      interval: 5s
      retries: 5

  redis:
    image: redis:7-alpine
    ports: ["6379:6379"]
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 5s

Migrations on deploy

Run prisma migrate deploy (or drizzle-kit migrate) as part of the deploy pipeline, before new code starts serving traffic. Two patterns:

# Option A: init container in Kubernetes (preferred — migrations run once before pods start)
initContainers:
  - name: migrate
    image: myapp:latest
    command: ["npx", "prisma", "migrate", "deploy"]

# Option B: CMD wrapper in a bare VM/ECS task
CMD ["sh", "-c", "npx prisma migrate deploy && node dist/server.js"]

Never run prisma migrate dev in production — it prompts interactively and may reset data.

Reverse proxy

# nginx — minimal reverse proxy config
server {
    listen 443 ssl http2;
    server_name api.example.com;

    location / {
        proxy_pass         http://localhost:3000;
        proxy_http_version 1.1;
        proxy_set_header   Upgrade $http_upgrade;
        proxy_set_header   Connection "upgrade";   # needed for WebSockets/SSE
        proxy_set_header   X-Real-IP $remote_addr;
        proxy_set_header   X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 3600s;                  # for SSE connections
        proxy_buffering    off;                    # flush SSE chunks immediately
    }
}

Or use Caddy (reverse_proxy localhost:3000) for automatic TLS with zero config.

Multi-environment config

.env                 # gitignored; local defaults
.env.development     # checked in; safe development defaults (no secrets)
.env.test            # checked in; test database URL, fake secrets
.env.production      # never exists on disk — all values injected by secret manager

Load order (dotenv convention): .env.{NODE_ENV}.local → .env.{NODE_ENV} → .env.local → .env. The Zod EnvSchema.parse(process.env) in config/env.ts (see 3c) crashes on startup if any required variable is missing — no silent misconfiguration in prod.

Graceful shutdown

const server = app.listen(3000);
for (const sig of ["SIGINT", "SIGTERM"]) {
  process.on(sig, () => {
    log.info("shutting down");
    server.close(() => {
      db.close().then(() => process.exit(0));
    });
    setTimeout(() => process.exit(1), 10_000).unref();  // force after 10s
  });
}

Config and secrets

  • All config via env vars; parse with Zod on startup; crash on invalid.
  • Never commit .env. Use secret managers in prod (AWS Secrets Manager, Vault, 1Password, Doppler).
  • Health endpoints: /healthz (liveness) and /readyz (checks DB/caches).
