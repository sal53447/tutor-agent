Runtimes — Node, Browser, Edge

The language is ECMAScript; everything else — files, sockets, the DOM, fetch — comes from the host. The same source runs in Node, in a browser tab, in a worker, and in an edge isolate, and the only thing that changes is which globals exist. Every later "why doesn't this work in production" in this curriculum (Next.js middleware on the edge, process.env being undefined in a client component, a library that imports node:fs) is a runtime-capability question, so learn to ask it first.

One language, three hosts

V8 (Chrome, Node, Cloudflare Workers) or JavaScriptCore (Safari, Bun) runs the language. The host then installs globals. Three capability tiers matter in practice:

  • ECMAScript — Promise, Map, Intl, structuredClone, globalThis. Everywhere.
  • Web-standard APIs — fetch, Request/Response, URL, TextEncoder, Web Streams, crypto.subtle, AbortController, setTimeout. Browsers, edge isolates, and Node ≥ 18 all ship these (the WinterCG minimum common API). Write to this tier and the code is portable.
  • Host-specific — Node: node:fs, node:http, process, Buffer. Browser: document, window, localStorage. Edge: the fetch handler export, bindings (KV, D1) passed in as env.

Gotcha

process.env.X in browser code does not read the environment — the bundler string-replaces it at build time (Vite: only import.meta.env.VITE_*; Next.js: only NEXT_PUBLIC_*). Anything else is undefined in the browser, and process itself is a ReferenceError unless the bundler shims it.

Mechanism

An edge isolate is the middle tier and nothing else. Code that only touches the top two tiers runs unchanged in all three hosts.

Python bridge

In Python the language and the standard library arrive together: import os works wherever CPython runs. JS has no bundled stdlib — the host is the stdlib. node:fs / node:path ≈ os / pathlib, but only in Node; process.env ≈ os.environ, but only in Node. The browser is Pyodide: the language is intact, os.fork does not exist. An edge isolate is a Lambda with a read-only tmpfs and no socket: only the request/response surface. The one cross-host API you can lean on is fetch + Request/Response, which is why modern Node servers and edge handlers converge on the same (Request) => Response shape.

Edge runtimes — V8 isolates, Web APIs only

Cloudflare Workers, Vercel Edge Functions and Deno Deploy run your module inside a V8 isolate: a sandbox the size of a browser tab, not a process. Startup is milliseconds because nothing boots; the trade is that there is no Node — no fs, no net, no process, usually no node:* at all (Workers polyfill a subset behind nodejs_compat). The program is a fetch handler: config arrives as the env argument, not a global.

export default {
  async fetch(request, env, ctx) {
    const url = new URL(request.url);
    if (url.pathname === "/health") return Response.json({ ok: true });

    const upstream = await fetch(env.API_URL + url.pathname, {
      headers: { authorization: `Basic ${btoa(`${env.USER}:${env.PASS}`)}` },
      signal: AbortSignal.timeout(2000),
    });
    ctx.waitUntil(logRequest(request));          // runs after the response is sent
    return new Response(upstream.body, { status: upstream.status });   // stream through
  },
};

This matters most in Next.js: middleware.ts runs on the edge runtime by default, so any import chain that reaches node:fs, a native module, or a database driver that opens TCP sockets fails at build time. Per-route code opts in with export const runtime = "edge" and gets the same constraints.

Do
const token = btoa(`${user}:${pass}`);              // Web API — Node, browser, edge
const hash  = await crypto.subtle.digest("SHA-256", data);
const env   = { apiUrl: process.env.API_URL };       // read once at the Node boundary, pass it down
Don't
const token = Buffer.from(`${user}:${pass}`).toString("base64");   // Node only
const hash  = createHash("sha256").update(data).digest("hex");       // node:crypto
fs.writeFileSync("./uploads/" + name, bytes);                        // no disk on edge; ephemeral on serverless

Node, Deno, Bun — the full runtimes

  • Node.js — the production default. LTS lines (22, 24) get 30 months of support; pin one in engines and .nvmrc. Ships fetch, Web Streams, crypto.subtle, a test runner (node --test), --watch, --env-file, and since 22.18 / 23.6 runs .ts files directly by type stripping (types erased, no type-checking, no enum/namespace). Prefix built-ins: import { readFile } from "node:fs/promises".
  • Deno — TypeScript-native, permission flags (--allow-net), Web-API-first, runs most npm packages via npm: specifiers. The design the others are converging on.
  • Bun — JavaScriptCore, very fast startup and install, bundler + test runner + package manager in one binary, broad Node compatibility. Common for tooling and scripts; production backends are still mostly Node.
// Node: the host-specific tier, by name
import { readFile } from "node:fs/promises";
import { createServer } from "node:http";

const cfg = JSON.parse(await readFile(new URL("./config.json", import.meta.url), "utf8"));
createServer((req, res) => res.end(cfg.greeting)).listen(process.env.PORT ?? 3000);
Gotcha

__dirname and require do not exist in ES modules. Use import.meta.url + new URL("./file", import.meta.url) (Node 20.11+ also has import.meta.dirname). A file that uses require under "type": "module" throws ReferenceError: require is not defined — the single most common Node-upgrade stack trace.

Code review
  • Node-only import in edge-bound code. node:fs, node:crypto, Buffer, native addons, TCP database drivers in middleware.ts or a runtime = "edge" route. Check the library's engines, its exports conditions ("workerd", "edge-light", "browser") and whether it has an HTTP-based driver (Neon, PlanetScale, Turso) before pulling it into the edge.
  • process.env read in shared or client code. It is undefined in the browser after bundling and absent on the edge. Read env once at the boundary (server entry, env argument) into a validated config object and pass it down.
  • Writing to local disk on serverless or edge. The filesystem is read-only, ephemeral, or absent, and never shared between instances. Uploads and generated files go to object storage (S3, R2, Blob).
  • Reading a Request/Response body twice. The stream is one-shot; the second read throws. clone() before logging, or read once and pass the parsed value along.
  • Unpinned Node version. No engines + .nvmrc/.node-version means CI, Docker and laptops drift; engines plus engine-strict=true in .npmrc fails the install loudly.
  • CommonJS assumptions in ESM. __dirname, require, module.exports under "type": "module". Use import.meta.url / import.meta.dirname and createRequire only for the rare CJS-only dependency.

Recall
Which API tier does portable JS target, and name four members of it.
The Web-standard (WinterCG) tier shared by Node, browsers and edge: fetch / Request / Response, URL, TextEncoder, Web Streams, crypto.subtle, AbortController, btoa.
What is an edge runtime, and what does it lack?
A V8 isolate (Cloudflare Workers, Vercel Edge, Deno Deploy) running a fetch(request, env, ctx) handler: millisecond cold starts, request-scoped, but no fs, no process, no TCP sockets, no node:* (beyond small compat shims).
What does this print? 
const res = new Response("{\"id\":7}", { headers: { "content-type": "application/json" } });
console.log(res.status, res.bodyUsed);
await res.json();
console.log(res.bodyUsed);
try { await res.text(); } catch (e) { console.log(e.name); }
200 false, true, TypeError. The body is a one-shot stream: default status 200, bodyUsed flips on first read, a second read throws in every host. clone() if you need two reads.
Why is process.env.API_KEY undefined in browser code even though it is set on the build machine?
Bundlers inline env at build time and only for allow-listed prefixes (VITE_*, NEXT_PUBLIC_*). There is no process in the browser; everything else is replaced with undefined or throws.
Web-API replacements for Buffer.from(s).toString("base64") and createHash("sha256")?
btoa(s) (ASCII) or Uint8Array.toBase64() for bytes; await crypto.subtle.digest("SHA-256", new TextEncoder().encode(s)) — async, returns an ArrayBuffer.
In an ES module under Node, what replaces __dirname and require?
import.meta.dirname (Node 20.11+) or new URL("./x", import.meta.url); import — or createRequire(import.meta.url) for a CJS-only dependency.
What does Node's type stripping (22.18+ / 23.6+) do and not do?
Runs .ts files by erasing type annotations — no type-checking, and no enum, namespace or parameter properties, which need real transforms.
