Server Actions — RPC with Forms

A function marked "use server" can be called directly from a client component. Next handles the RPC, serialization, and progressive enhancement. Forms submit without JS; validation and mutation live in the same place.

Typed action signature + useActionState

useActionState is the React 19 / Next 15 API. The old name useFormState (from react-dom) still works but is deprecated — prefer useActionState from react.

// app/actions.ts
"use server";
import { z } from "zod";
import { redirect } from "next/navigation";
import { revalidatePath } from "next/cache";  // see 5d for cache invalidation

const CreatePost = z.object({ title: z.string().min(1), body: z.string() });

type State = { error?: string; fieldErrors?: Record<string, string[]> };

// Typed signature: (prevState, formData) => Promise<State>
export async function createPost(prev: State, formData: FormData): Promise<State> {
  const parsed = CreatePost.safeParse(Object.fromEntries(formData));
  if (!parsed.success) {
    return { fieldErrors: parsed.error.flatten().fieldErrors };
  }

  try {
    await db.posts.create(parsed.data);
  } catch (err) {
    console.error("createPost failed:", err);   // log server-side only
    return { error: "Failed to save post. Please try again." };
  }

  revalidatePath("/posts");    // purge cached route — see 5d
  redirect("/posts");          // redirect after successful mutation
}
// app/new-post/page.tsx
"use client";
import { useActionState } from "react";   // React 19 — not react-dom
import { createPost } from "../actions";
import { SubmitButton } from "@/components/submit-button";

export default function NewPost() {
  // useFormState (deprecated) → useActionState (React 19 / Next 15)
  const [state, formAction] = useActionState(createPost, {});
  return (
    <form action={formAction}>
      <input name="title" />
      {state?.fieldErrors?.title && <span>{state.fieldErrors.title[0]}</span>}
      <textarea name="body" />
      <SubmitButton />
      {state?.error && <p role="alert">{state.error}</p>}
    </form>
  );
}

Progressive enhancement

When the action prop receives a server action directly (not formAction from a hook), the form works without any client-side JS — standard HTML form submission.

// app/newsletter/page.tsx — works with JS disabled
import { subscribe } from "./actions";

export default function NewsletterPage() {
  return (
    <form action={subscribe}>  {/* plain server action — no "use client" needed */}
      <input name="email" type="email" required />
      <button type="submit">Subscribe</button>
    </form>
  );
}
Gotcha — useFormState deprecation

useFormState from react-dom is deprecated in React 19. Use useActionState from react. The signature is identical; only the import and name changed. Old tutorials and codebases will show the old name.

Python bridge

A Django form POST view — validate, save, redirect — is exactly the server action pattern. form.is_valid() → Zod parse. form.save() → DB call. return redirect("/") → redirect("/posts"). The mental model is identical; the wire protocol is RPC instead of HTTP form POST.

When to pick this over a route handler

Server actions are ideal for mutations tied to forms or specific UI. Route handlers (app/api/.../route.ts) are for public API endpoints, webhooks, or when you need HTTP semantics. Same power, different seams.
