Code Quality — ESLint & Prettier

Two tools, two jobs. Prettier formats (whitespace, quotes, semicolons). ESLint catches bugs and enforces patterns. Don't confuse them.

Prettier

  • Opinionated. Almost no config. Run on save.
  • One debate ends when Prettier arrives: "tabs vs spaces", "single vs double quotes" — Prettier picks, team moves on.

ESLint — the rules that earn their keep

Modern stack: flat config (eslint.config.js), @typescript-eslint for TS projects. Recommended starter: eslint-config-eslint or an opinionated preset like @antfu/eslint-config (one popular choice — not a canonical standard; evaluate whether its opinions match your team's).

// Non-negotiable rules
"eqeqeq": "error",                                     // always ===
"no-var": "error",                                     // use const/let
"prefer-const": "error",
"@typescript-eslint/no-floating-promises": "error",    // await your promises
"@typescript-eslint/no-misused-promises": "error",
"no-unused-vars": "warn",
"no-implicit-coercion": "warn",
"react-hooks/rules-of-hooks": "error",                 // React
"react-hooks/exhaustive-deps": "warn"                  // React
Python bridge

Prettier is Black. ESLint is Ruff / flake8 / pyflakes. You want both, configured in pre-commit or editor-on-save.

Enforcing at commit time — Husky + lint-staged

Husky installs Git hooks into your repo. lint-staged runs linters only on staged files (fast — no full-repo scan on every commit).

pnpm add -D husky lint-staged
npx husky init
// package.json
{
  "lint-staged": {
    "*.{js,ts,tsx}": ["eslint --fix", "prettier --write"],
    "*.{json,md,css}": ["prettier --write"]
  }
}

The pre-commit hook (at .husky/pre-commit) runs npx lint-staged. Commits that fail lint are rejected before they hit CI. This is the standard enforcement mechanism in most JS/TS teams.
