Part 1 · JavaScript · 1d

Arrays, Iteration, and Generators

Arrays are objects with numeric keys and a length. They're your list, tuple, and deque — use them for everything sequential. Map and Set exist for dict-like and set-like use cases.

The daily methods

[1,2,3].map(x => x * 2);            // [2,4,6]
[1,2,3].filter(x => x > 1);          // [2,3]
[1,2,3].reduce((a, b) => a + b, 0);  // 6
[1,2,3].find(x => x > 1);            // 2
[1,2,3].some(x => x > 2);            // true
[1,2,3].every(x => x > 0);           // true
[1,2,3].includes(2);                 // true
[[1,2],[3]].flat();                  // [1,2,3]
[1,2,3].flatMap(x => [x, -x]);       // [1,-1,2,-2,3,-3]
[1,2,3].slice(0, 2);                 // [1,2] (copy)
[1,2,3].toSorted();                  // [1,2,3] (immutable sort, ES2023)
[1,2,3].sort();                      // in-place! mutates!

reduce beyond sums — building an index

reduce is general-purpose fold. The most useful real-world form: turning an array into a keyed object.

const users = [
  { id: 1, name: "Alice" },
  { id: 2, name: "Bob" },
];

// Array → object index (O(1) lookup by id)
const byId = users.reduce((acc, user) => {
  acc[user.id] = user;
  return acc;
}, {});
// { 1: { id: 1, name: "Alice" }, 2: { id: 2, name: "Bob" } }

// Grouping
const byRole = users.reduce((acc, user) => {
  (acc[user.role] ??= []).push(user);
  return acc;
}, {});
Mutation traps

sort, reverse, splice, push, pop, shift, unshift, fill mutate the array. Newer immutable twins exist: toSorted, toReversed, toSpliced, with. In React state, always prefer the immutable versions or spread.

Map

Map is a key-value store where keys can be any value — not just strings. It preserves insertion order and has O(1) lookup. Prefer it over plain objects when keys are dynamic, non-string, or when you need size/iteration guarantees.

const m = new Map();
m.set("a", 1);
m.set({ id: 1 }, "object key");  // any value as key
m.get("a");         // 1
m.has("a");         // true
m.delete("a");
m.size;             // number of entries

// Construct from entries
const m2 = new Map([["x", 10], ["y", 20]]);

// Iteration — insertion order guaranteed
for (const [key, value] of m2) {
  console.log(key, value);
}
[...m2.keys()];
[...m2.values()];
[...m2.entries()];
Python bridge

Map is JS's dict. Plain objects ({}) look dict-like but have prototype baggage and only allow string/symbol keys. For anything beyond simple config-style objects, reach for Map.

Set

Set stores unique values in insertion order. Membership check is O(1).

const s = new Set([1, 2, 2, 3]);  // {1, 2, 3} — duplicates removed
s.add(4);
s.has(2);           // true
s.delete(2);
s.size;             // 3

// Deduplication pattern
const unique = [...new Set(arr)];

// Iteration
for (const v of s) { ... }

// Set operations (no built-in union/intersect until ES2024 Set methods)
const union        = new Set([...a, ...b]);
const intersection = new Set([...a].filter(x => b.has(x)));

Iterator protocol and for...of

Any object with a [Symbol.iterator]() method that returns {next(): {value, done}} is iterable. for...of works on iterables. Arrays, Maps, Sets, strings, and generators are iterable out of the box.

// Good
for (const x of [1,2,3]) {...}
for (const [k, v] of Object.entries(obj)) {...}
for (const [i, x] of arr.entries()) {...}

// Almost never what you want: iterates over enumerable string keys, including inherited
for (const k in obj) {...}

Generators — same as Python

function* range(n) {
  for (let i = 0; i < n; i++) yield i;
}
[...range(3)];            // [0, 1, 2]
for (const x of range(3)) { ... }
Python bridge

function* with yield is identical to Python's def with yield. Async generators exist too (async function* + for await) — use them for streams, paginated APIs, long-polling. In data work you'll reach for these more than most JS devs.

Self-check — mutating vs immutable methods
1. Which of these mutate the original array: map, filter, push, slice, splice, sort, toSorted?

Mutating: push, splice, sort. Non-mutating (return new array/value): map, filter, slice, toSorted.

2. You want to remove duplicates from const ids = [3, 1, 2, 1, 3]. What's the one-liner?

const unique = [...new Set(ids)]; — Set deduplicates, spread converts back to array.

3. You have const arr = [1, 2, 3]; const copy = arr; copy.push(4);. What is arr?

[1, 2, 3, 4]. copy is a reference, not a clone. To clone: const copy = [...arr] or arr.slice().
