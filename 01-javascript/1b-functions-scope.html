Part 1 · JavaScript · 1b

Functions, Closures, and this

Functions are first-class values: you pass them around, return them, store them in variables. JS leans heavily on higher-order functions — more than Python culturally does.

Three function forms

// 1. Function declaration — hoisted, has its own `this`, has `arguments`
function add(a, b) { return a + b; }

// 2. Function expression — not hoisted, otherwise same
const add = function(a, b) { return a + b; };

// 3. Arrow function — not hoisted, NO own `this`, NO `arguments`, cannot be `new`'d
const add = (a, b) => a + b;

Arrow functions are not just shorter syntax. They capture this lexically from the enclosing scope. This is often what you want — and occasionally exactly what you don't.

Hoisting and the Temporal Dead Zone

Function declarations are fully hoisted — you can call them before the line they appear on. let/const bindings (including function expressions assigned to them) exist in a Temporal Dead Zone (TDZ) from the top of the block until the declaration is reached. Accessing them in the TDZ throws a ReferenceError.

// Function declaration — fine, fully hoisted
greet("world");               // "hello world"
function greet(name) { return `hello ${name}`; }

// const function expression — TDZ
sayBye("world");              // ReferenceError: Cannot access 'sayBye' before initialization
const sayBye = (name) => `bye ${name}`;
Gotcha

var declarations are hoisted (to undefined), which is why calling a var-assigned function before the assignment returns TypeError: sayBye is not a function — a different and more confusing failure mode. Another reason to never use var.

Class field arrow functions — modern this binding

When you need a method that is safe to pass as a callback (e.g., a React event handler), declare it as a class field arrow. The arrow is created per-instance with this already bound — no .bind(this) needed.

class Button {
  label = "Click me";

  // Arrow field: `this` is always the instance, even when passed as a callback
  handleClick = () => {
    console.log(this.label);
  };
}

const btn = new Button();
document.addEventListener("click", btn.handleClick); // works, no bind needed

...rest replaces arguments

// Old: `arguments` is array-like, not a real array, doesn't exist in arrow functions
function old() { console.log(arguments[0]); }

// New: rest is a real array, works in any function form
const sum = (...nums) => nums.reduce((a, b) => a + b, 0);

Closures — the real workhorse

A closure is a function plus the variables it captured from its enclosing scope. Identical to Python closures, but used much more idiomatically in JS.

function makeCounter() {
  let count = 0;                       // captured
  return {
    inc: () => ++count,
    get: () => count,
  };
}
const c = makeCounter();
c.inc(); c.inc();
c.get();  // 2 — count is private and shared between the two methods
Python bridge

Python has closures (nested def), but the culture prefers classes for anything stateful. JS uses closures for private state, module state, event handlers, and anywhere you'd reach for a class in Python. Recognize this pattern — you'll see it constantly.

The this keyword — four binding rules

this is decided at call time, not definition time. That's the entire trick.

// 1. Default — `this` is undefined (strict) or global (sloppy)
function show() { console.log(this); }
show();

// 2. Implicit (method call) — `this` is the object before the dot
const obj = { name: "x", show() { console.log(this.name); } };
obj.show();           // "x"

// 3. Explicit — `.call`, `.apply`, `.bind`
show.call({ name: "y" });

// 4. `new` — `this` is the freshly created instance
function Foo() { this.x = 1; }
new Foo();            // { x: 1 }
The classic trap

When you pass a method as a callback, it loses its this: setTimeout(obj.show, 100) logs undefined. Fixes: setTimeout(() => obj.show(), 100) or setTimeout(obj.show.bind(obj), 100). Arrow functions solve this by not having their own this — they inherit from the enclosing scope.

Code review
  • Use arrow functions by default. Use regular functions only when you need this (class methods, object methods) or hoisting.
  • Never rely on this in a plain utility function. If you find yourself debugging this, refactor toward explicit parameters.
  • In React, function components + hooks have no this. It's a non-issue there.
