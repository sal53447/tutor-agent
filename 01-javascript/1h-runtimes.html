Runtimes — Node, Browser, Edge

The same JS language runs in different environments with different APIs. Knowing what runs where is a big part of "writing modern JS."

Edge runtimes (Cloudflare Workers, Vercel Edge Functions, Deno Deploy) are V8 isolates — no Node APIs. You can't use fs or most of node:*. You use Web APIs (fetch, Web Streams, crypto.subtle). This matters a lot in Next.js where middleware runs on edge.

Alternative full runtimes: Deno (TypeScript-native, permission model, Web API-first, can run some npm packages) and Bun (extremely fast startup, built-in bundler/test runner, mostly Node-compatible). Same JS/TS language — different built-in APIs and tooling surface. Most production backends still target Node, but Bun is increasingly used for tooling and edge-adjacent workloads.

Code review
  • A library that works in Node but not edge is a footgun in Next.js middleware. Check package.json engines and the docs.
  • Don't assume process.env exists — in the browser it doesn't (bundlers inline build-time values).
  • Don't write to disk on serverless; use object storage (S3, R2).
