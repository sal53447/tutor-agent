Part 3 · Express · 3g

Observability — Logs, Metrics, Traces

Structured logging with pino

import pino from "pino";
const log = pino({ level: process.env.LOG_LEVEL ?? "info" });

log.info({ userId, orderId }, "order created");
log.error({ err }, "failed to charge card");

One JSON object per line. Ingestable by Datadog, Grafana Loki, CloudWatch. Never use console.log in server code — no level, no structure, no correlation.

pino-http — automatic request logging

import pinoHttp from "pino-http";

// Mount before routes so every request gets logged
app.use(pinoHttp({
  logger: log,
  customLogLevel: (req, res, err) => {
    if (err || res.statusCode >= 500) return "error";
    if (res.statusCode >= 400) return "warn";
    return "info";
  },
  // Redact sensitive fields from the log output
  redact: ["req.headers.authorization", "req.body.password"],
  // Attach requestId from res.locals if requestId middleware ran first
  genReqId: (req) => req.headers["x-request-id"] ?? randomUUID(),
}));
// Each request now automatically logs: method, url, statusCode, responseTime, requestId

Request IDs and correlation

Generate a UUID per request; attach to a logger; pass through service calls. When an error happens in production, one line gives you the full trail. See 3b for the requestId middleware implementation; wire it before pinoHttp so the ID is available when the request logger initializes.

Health and readiness endpoints

// /healthz — liveness: is the process alive?
// Kubernetes kills and restarts the pod if this fails.
app.get("/healthz", (req, res) => res.json({ ok: true }));

// /readyz — readiness: can this instance accept traffic?
// Kubernetes stops routing traffic to the pod while this returns non-200.
app.get("/readyz", async (req, res) => {
  try {
    await prisma.$queryRaw`SELECT 1`;           // check DB
    await redisClient.ping();                    // check cache
    res.json({ ok: true });
  } catch (err) {
    res.status(503).json({ ok: false, error: String(err) });
  }
});

Keep /healthz trivial — it must never fail due to downstream dependencies. /readyz is the one that checks dependencies; a failing readiness probe takes the pod out of rotation gracefully.

Python bridge

pino ≈ structlog (or Python's logging with JSON formatter). Both produce one JSON object per log call; both support child loggers that inherit bound fields (like requestId). pino-http auto-middleware ≈ Django's request logging middleware or FastAPI's access log. The health/readiness split is Kubernetes-native and identical regardless of language.

Metrics and tracing

  • Metrics — counters/gauges/histograms. prom-client + Prometheus; or managed (Datadog, New Relic).
  • Tracing — OpenTelemetry. Each request is a trace; each hop is a span. Essential for microservices.
  • Error tracking — Sentry. Auto-captures exceptions with source maps and context.
The three things to wire on day one
  1. Pino with request ID middleware, log level via env, JSON output.
  2. Sentry SDK in app.ts before routes, with env-based DSN.
  3. A /metrics endpoint or OpenTelemetry exporter wired to your infra.
