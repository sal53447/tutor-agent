Part 3 · Express · 3j

When Express Isn't the Answer

Express is the incumbent but not always the best tool. Know the alternatives.

ToolPick when
ExpressYou need a battle-tested, unopinionated framework with the biggest middleware ecosystem.
FastifyThroughput matters. ~2x faster than Express. Built-in schema validation. Excellent plugin system.
KoaYou want Express without the legacy baggage. Async-first (no callback-based next(err)). Smaller, leaner. Less ecosystem than Express but cleaner internals.
HonoYou target the edge (Cloudflare, Vercel Edge). Tiny, Web-Standards-based, ultra-fast cold starts.
ElysiaBun runtime. End-to-end type inference from schema to handler with zero codegen. Worth watching; Bun ecosystem.
NestJSLarge team, want opinionated structure, DI, decorators, Angular-like architecture.
tRPCYou own both ends (Next.js + Node) and want end-to-end type safety without OpenAPI ceremony. Procedures are defined once on the server; the client gets auto-inferred TypeScript types with no code generation step — calling an API feels like calling a local function.
Next.js API routes / Server ActionsYou're already on Next.js. Often you don't need a separate Express service at all.
Python bridge

If you're coming from FastAPI, Fastify is the closest analogue: schema-first, fast, plugin system maps well to FastAPI's dependency injection. Hono ≈ Starlette (minimal, standards-based, deployable anywhere). NestJS ≈ Django (opinionated, batteries-included, decorator-driven). tRPC has no direct Python equivalent — the closest conceptual analogue is a Python monorepo where FastAPI Pydantic models are also imported by the frontend, but tRPC automates this entirely.

Rule of thumb 2026

Full-stack Next.js app? Use route handlers + server actions; no separate backend. Dedicated API service? Fastify if performance matters, Express if team familiarity does, Hono if you deploy to edge. NestJS only if the team explicitly wants that architectural style.
