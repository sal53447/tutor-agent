Middleware & Edge Runtime

// middleware.ts at project root
import { NextResponse } from "next/server";

export function middleware(req) {
  const token = req.cookies.get("session")?.value;
  if (!token && req.nextUrl.pathname.startsWith("/dashboard")) {
    return NextResponse.redirect(new URL("/login", req.url));
  }
}

export const config = {
  matcher: ["/dashboard/:path*", "/api/private/:path*"],
};

Middleware runs on every matched request before routing. Great for auth gating, redirects, rewrites, A/B bucketing. Runs on Edge Runtime (V8 isolate) — no Node APIs, no heavy dependencies, no long-lived work. Keep it fast.

Advanced matcher config

The matcher array accepts path strings or objects with source, has, and missing for conditional matching.

export const config = {
  matcher: [
    // String shorthand
    "/dashboard/:path*",
    // Object form: match only when the header is present
    {
      source: "/api/:path*",
      has: [{ type: "header", key: "x-api-key" }],
    },
    // Object form: skip when a cookie is set (bypass for internal tools)
    {
      source: "/:path*",
      missing: [{ type: "cookie", key: "bypass-middleware" }],
    },
  ],
};

Auth in middleware — verify JWT directly

Don't import your full Auth.js config into middleware — it pulls in DB drivers that won't run on the Edge. Verify the JWT with jose (a pure-JS JOSE library) instead.

// middleware.ts
import { jwtVerify } from "jose";
import { NextResponse } from "next/server";

const secret = new TextEncoder().encode(process.env.AUTH_SECRET!);

export async function middleware(req) {
  const token = req.cookies.get("session")?.value;

  if (!token) {
    return NextResponse.redirect(new URL("/login", req.url));
  }

  try {
    await jwtVerify(token, secret);   // throws if invalid / expired
    return NextResponse.next();
  } catch {
    return NextResponse.redirect(new URL("/login", req.url));
  }
}

export const config = { matcher: ["/dashboard/:path*"] };

Rate limiting example

Counter stored in Upstash Redis (HTTP-based, works in Edge). Returns 429 when a client exceeds the limit.

// middleware.ts
import { Redis } from "@upstash/redis/cloudflare";
import { NextResponse } from "next/server";

const redis = Redis.fromEnv();
const LIMIT = 60;  // requests per window
const WINDOW = 60; // seconds

export async function middleware(req) {
  const ip = req.headers.get("x-forwarded-for") ?? "anon";
  const key = `rate:${ip}`;

  const count = await redis.incr(key);
  if (count === 1) await redis.expire(key, WINDOW);

  if (count > LIMIT) {
    return new NextResponse("Too Many Requests", { status: 429 });
  }
  return NextResponse.next();
}

export const config = { matcher: ["/api/:path*"] };
Edge constraints to remember
  • No Node built-ins (fs, path, most of node:*).
  • No long-lived connections (DB drivers usually need an HTTP-based alternative like Neon serverless or Prisma Accelerate).
  • CPU time limit (~50ms on Vercel Edge), not a wall-clock timeout. Middleware must finish fast; it blocks every request on every matched path. The "30s" figure in older docs refers to Edge Function wall time, not middleware CPU budget.
  • Packages with native bindings (bcrypt, sharp) won't run. Use bcryptjs or move to a Node route.
  • Don't run full Auth.js in middleware — verify JWTs with jose directly (see example above).
