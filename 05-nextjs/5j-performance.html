Part 5 · Next.js · 5j

Performance — Core Web Vitals, Images, Fonts

The vitals that matter (2026)

  • LCP (Largest Contentful Paint) < 2.5s — the hero image or text.
  • INP (Interaction to Next Paint) < 200ms — responsiveness to clicks / keystrokes. Replaced FID.
  • CLS (Cumulative Layout Shift) < 0.1 — don't move things while the user is reading.

The built-in levers

  • next/image — serves modern formats (AVIF/WebP), lazy-loads, enforces width/height (no CLS). Add priority to the above-the-fold image to preload it as an LCP candidate.
  • next/font — self-hosts Google fonts at build; no render-blocking network request.
  • Server components — ship less JS. RSC payload is smaller than component JS + data.
  • Streaming + Suspense — show shell fast, stream in expensive parts.
  • loading.tsx — instant feedback during navigation.
// Preload the hero image — tells the browser this is the LCP element
import Image from "next/image";

export function Hero() {
  return (
    <Image
      src="/hero.jpg"
      alt="Hero"
      width={1200}
      height={600}
      priority          // preloads; skip lazy-load for above-the-fold images
    />
  );
}

Lazy-loading client components — next/dynamic

Large client components (rich text editors, chart libraries, map widgets) should be code-split and loaded only when needed. next/dynamic is React.lazy with SSR control built in.

import dynamic from "next/dynamic";

// Code-split: only loads when rendered. SSR disabled for browser-only libs.
const RichEditor = dynamic(() => import("@/components/rich-editor"), {
  ssr: false,
  loading: () => <p>Loading editor…</p>,
});

// Use it like any component — JS loads on demand
export function PostEditor() {
  return <RichEditor />;
}

Third-party scripts — next/script

Plain <script> tags in layouts block rendering. next/script gives you loading strategies:

import Script from "next/script";

// afterInteractive (default): loads after page is interactive. Good for analytics.
<Script src="https://analytics.example.com/script.js" strategy="afterInteractive" />

// lazyOnload: loads during browser idle time. Good for chat widgets, low-priority widgets.
<Script src="https://widget.example.com/chat.js" strategy="lazyOnload" />

// beforeInteractive: loads before hydration (rare — use for polyfills only).
<Script src="/polyfill.js" strategy="beforeInteractive" />

Bundle analysis

Find what's inflating your client bundle before it becomes a problem.

npm install --save-dev @next/bundle-analyzer
// next.config.js
const withBundleAnalyzer = require("@next/bundle-analyzer")({
  enabled: process.env.ANALYZE === "true",
});
module.exports = withBundleAnalyzer({});

// Then:
// ANALYZE=true next build  — opens interactive treemap in browser
The biggest single win

Move client-fetched data to server components. Every useEffect(() => fetch(...)) you remove is one round-trip and one JS bundle the user doesn't wait for. This is why RSC exists.
